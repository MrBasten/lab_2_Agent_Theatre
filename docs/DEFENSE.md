# Короткие ответы для защиты

## Что демонстрировать

1. Откройте `LLM_Theatre.ipynb`: замысел, полный код и вымышленный корпус находятся в ячейках. Сохранённый demo подписан как сценарная фикстура.
2. Откройте сохранённую пьесу в `outputs/cloud/play.html`. В `play.json` покажите план, реальные модели в `metadata.models` и значение `fixture=false`.
3. В `events` найдите последовательность `generation → tool → generation`: актёр сам запрашивает поиск и получает реальное содержимое файла. Покажите, как найденное свидетельство связано с последующей репликой.
4. Найдите `selection`: сравните предложение модели-режиссёра с фактическим говорящим и объяснением ограничения.
5. Включите фрагмент `outputs/cloud/audio_piper/play.wav` и покажите соответствие голосов ролям в манифесте. Сценическая редакция с собственной записью находится в `outputs/edited/`.

## Почему это несколько агентов

Агенты имеют отдельные системные инструкции, цели и состояние. Каждый актёр видит собственную тайну и свои наблюдения. Остальные получают опубликованные реплики. Фактическое распределение Alice AI LLM Flash и YandexGPT Pro 5.1 указано в метаданных пьесы.

## Как выбирается следующий говорящий

Отдельная LLM предлагает персонажа и драматургическую причину. Код запрещает немедленный повтор, защищает от длительного выпадения и обеспечивает участие всех троих в действии. Корректное предложение режиссёра среди ещё не выступавших сохраняется. Вынужденная замена отмечается в журнале. Это объяснимый механизм, а не заранее записанная последовательность реплик.

## Где макропланирование

Первый запрос создаёт общий JSON-план с целью, открытием и завершением каждого действия. Сцены и реплики генерируются позже с учётом этого плана. Наличие полей плана само по себе не гарантирует хорошую драматургию — это нужно оценить по фактической пьесе.

## Как устроены инструменты

Модель возвращает JSON-действие. Оркестратор вызывает `ToolBox`, добавляет результат в контекст и снова вызывает актёра. Есть поиск по UTF-8 документам, чтение по ID и калькулятор сметы. На ход разрешены два инструмента. Это собственный протокол function calling; подключение специального агентского фреймворка для него не требуется.

## Что проверяют ссылки

ID в `citations` должен ранее попасть к этому актёру из успешного ответа инструмента. Это подтверждает происхождение ссылки. Соответствие каждого утверждения смыслу документа такая проверка не доказывает: локальный прогон показал и смысловые ошибки. Документы вымышлены, а не выданы за исторические источники.

## Что получилось при проверке моделей

Малая Qwen3-1.7B технически завершила базовый прогон, но повторяла реплики и смешивала роли. Её результат сохранён с предупреждением. Для основной локальной роли выбрана Qwen3-4B-Instruct-2507. Дословные повторы и явное обращение к самому себе теперь вызывают ограниченный запрос исправления. Между экспериментами менялись и промпты, поэтому сравнение моделей не является контролируемой абляцией.

## Какие ограничения назвать честно

Ограниченный контекст может терять детали. Проверка ID подтверждает происхождение ссылки. Смысл реплики проверяется по самому документу. Облачный seed не гарантирует точного повторения. Критерий локальной LLM для основного прогона не заявляется.

## Как раскрыто использование ИИ

В `docs/AI_USAGE.md` сохранён исходный запрос и описание работы кодинг-агентов; в `docs/IDEA.md` — замысел, в `theatre/prompts.py` и ноутбуке — промпты ролей. Автору нужно заполнить ФИО и добавить личные наблюдения после чтения и прослушивания результатов.
